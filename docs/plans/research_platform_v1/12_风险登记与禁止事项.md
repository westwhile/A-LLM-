# 风险登记与禁止事项

## 2. A-LLM 禁止事项

- 不把 sample、合成夹具或短历史输出表述为真实研究；
- 不在数据冻结前运行并解释正式模型；
- 不使用随机时间切分、未来成分、未滞后财务数据或 smoothed HMM 概率；
- 不根据最终留出期表现修改模型、参数或门槛；
- 不把多空因子诊断当作 A 股可交易做空收益；
- 不为得到好结果删除异常数据、放宽成本或更改失败条件；
- 不自动 commit、tag、push、发布或删除旧批次；
- 不把受限 raw/standard 数据、outputs、tmp 或凭据加入发布包。

## 3. ML/LLM 禁止事项

- 不在全样本上拟合预处理、降维、特征选择或 Embedding 监督变换；
- 不把模型置信度解释为投资成功概率；
- 不因使用 LightGBM、Transformer、RAG 或 Agent 就宣称创新；
- 不使用未审查的历史新闻、当前网页回填或重复转载构造事件；
- 不把授权文本、个人财务数据或凭据发送给未批准外部模型；
- 不自动根据 LLM 输出修改组合或 PFROS 事实；
- 不在结构化基准未完成前启动基础模型微调或 RL。

## 4. PFROS 禁止事项

- 不允许研究、Dashboard 或 AI 直接写 Financial Book；
- 不覆盖原始金融事件，错误必须通过冲正/更正；
- 不在测试、日志、Git 或 AI 对话中放入真实账号、身份、余额和流水；
- 不把批准记录当作真实成交，执行后仍以券商/银行来源入账；
- 不在账本、重放、对账和恢复未通过前建设复杂投资模型；
- 不将个人结果未经治理自动回流为训练数据。

## 5. 生产与交易边界

当前计划不授权：券商连接、下单、撤单、自动调仓、资金转移或生产账户操作。未来如增加任一能力，必须：

1. 用户在独立任务中明确授权；
2. 执行 `trading-safety-review`；
3. 设计限额、双重批准、模拟、熔断、告警、审计和恢复；
4. 先在完全隔离的 paper/sandbox 环境验收；
5. 不因本计划存在而推定任何实盘权限。

## 6. 停止规则

遇到以下情况立即停止当前阶段：

- 来源、许可、哈希或签署不一致；
- blocking、测试失败或证据缺失；
- 数据或结果路径超出授权范围；
- 最终留出期已被污染；
- 个人敏感数据可能泄漏；
- 任务需要新网络、依赖、外部服务、数据库迁移或交易权限但未获批准；
- 为推进进度必须改变研究问题或放宽门槛。

停止后将状态设为 `blocked` 或 `review`，记录证据和解除方式，不用推测填补缺口。
