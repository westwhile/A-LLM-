# Section Contracts：计划文件职责合同

## 总流程计划

- 目的：定义系统边界、中央问题、阶段和完成定义；
- 输入：当前实现、PFROS 架构、用户路线草稿；
- 允许声明：当前已核验工程事实与拟实施阶段；
- 禁止声明：模型有效、PFROS 改善收益、自动交易；
- 验证：所有阶段可追溯到专项计划和门禁。

## P0 基线冻结

- 目的：闭合哈希、测试、数据门禁和签署；
- 输入：当前工作树、manifest、gate、signoff；
- 允许声明：当前差异与待办；
- 禁止声明：AI 已完成用户签署或 Git 发布；
- 验证：证据一致且人工批准完整。

## P1 真实传统基准

- 目的：在真实 OOS 中评价现有传统/动态方案；
- 输入：P0 冻结数据和协议；
- 允许声明：支持、不支持或证据不足；
- 禁止声明：回测收益可实盘获得；
- 验证：≥36 OOS 月、成本、消融、过拟合和留出期。

## P2 科研平台注册层

- 目的：实现可追踪和跨仓库证据交接；
- 输入：现有 run/evidence manifest；
- 允许声明：拟实现 schema、registry 和 package；
- 禁止声明：在线 MLOps 或模型自动晋级；
- 验证：合同、哈希篡改、sample/real 成熟度测试。

## P3/P4/P5 科研实验

- 目的：按 R1/P4 LLM 表示、R2/P3 ML Alpha、R3/P5 组合转化顺序检验；
- 输入：上一阶段 accepted 证据；
- 允许声明：预注册假设与可否定结果；
- 禁止声明：复杂模型必然更好；
- 验证：透明对照、泄漏审计、消融、成本、稳定性和留出期。

## PFROS M0–M7

- 目的：建立可信个人金融事实、分析和决策闭环；
- 输入：PFROS 独立项目批准与 Research Package；
- 允许声明：协调依赖与验收；
- 禁止声明：本计划已经实现 PFROS 代码或真实数据导入；
- 验证：重放、对账、恢复、隐私、人工批准不可绕过。

## 门禁、依赖、实验和风险文件

- 目的：统一状态、WIP、登记、结论语言和停止规则；
- 禁止声明：任何日历日期自动代表完成；
- 验证：没有冲突阶段编号、状态词或授权边界。

## modules 专项研究文件

- 目的：把扩展方向变成可单独学习、预注册、实现、验收和停止的研究模块；
- 共同输入：主线门禁、当前实现、用户研究方向和已核验核心来源；
- 必备字段：中央问题、先修、方法阶梯、实验/负对照、交付物、退出门、阅读路线和来源状态；
- 允许声明：候选方法、已核验文献元数据、建议依赖关系；
- 禁止声明：模块已实现、论文方法在 A 股有效、所有模块均需实施；
- 验证：模块链接存在、优先级与主线一致、探索项不能绕过 L0–L5。

## 三大科研主线与 AI 工程分工

- 目的：把个人学习、论文与实验顺序固定为 R1 LLM → R2 ML → R3 Portfolio；
- 输入：用户本轮优先级选择、现有 P0–P5 门禁和模块计划；
- 允许声明：AI 可承担经批准的工程实现与证据整理；
- 禁止声明：AI 可替代数据许可、预注册、最终留出、科研判断、PFROS 批准或真实资金操作；
- 验证：R1 固定 evaluator、R2 固定表示、R3 固定预测，三阶段不互相回看最终留出期；
- 接口：`TextRepresentationArtifact → AlphaPredictionArtifact → PortfolioResearchArtifact → Research Package`。

### 工程底座模块

- 01/03/07/08/14/16 服务三大真实科研主线；
- 由 AI 按需实现并接受人工验收；
- 失败时优先修复证据链，不扩大模型复杂度。

### B/C 层模块

- B 层需直接前置门；C 层默认只允许可行性备忘录；
- 异常检测、合成数据、Agent、RL 有专门非自动执行边界；
- 因果 ML 使用独立 estimand/识别合同，不与预测结论混写。
