# 三大科研主线与 AI 工程分工计划

> 状态：`planning`
>
> 决策日期：2026-08-11
>
> 本文件是个人科研学习与论文优先级的权威入口。P3/P4/P5 继续作为已有文件编号使用，但科研执行顺序固定为 `R1 → R2 → R3`。

## 1. 总体决策

个人投入的科研主线只保留三个：

1. **R1：LLM Event Factor**——研究金融文本如何形成可验证的事件表示；
2. **R2：Machine Learning Alpha Model**——研究结构化特征、ESG 与冻结文本表示如何共同预测横截面收益；
3. **R3：Portfolio Optimization**——研究预测增量如何在估计误差、风险、成本和约束下转化为组合价值。

其他模块不作为独立论文主线，定位为：

- 三大研究方向的共同基础设施；或
- 由明确需求触发的 AI 辅助工程任务；或
- 暂不实现的长期候选。

“AI 辅助实现”不等于 AI 自动验收。数据许可、PIT、研究假设、最终留出、科研结论、PFROS 决策和任何真实执行仍由人负责。

## 2. 为什么 R1 可以先于 R2

LLM 表示必须通过收益预测任务评价，因此 R1 仍需要一个模型评价器，但不需要先完成完整的 ML Alpha 研究。

R1 使用冻结、低搜索预算的评价器：

```text
传统结构化特征 + 候选文本表示
              ↓
固定 Linear / 固定 LightGBM evaluator
              ↓
OOS 预测增量、IC、覆盖与成本敏感性
```

这里的 LightGBM 只承担“测量文本表示是否有信息”的角色，不研究大规模模型选择。R2 才系统比较 Elastic Net、LightGBM、Random Forest、浅层神经网络、AutoEncoder/深层资产定价方法。

这避免两个错误：

- 没有预测器，R1 只能评价情绪分类准确率，无法回答 Alpha 问题；
- 在 R1 同时大规模调文本模型和收益模型，会无法识别增量来自表示还是预测器。

## 3. R1：LLM Event Factor

### 3.1 中央问题

> 在真实文本来源、严格事件时点、去重和固定收益评价器下，金融文本表示是否相对无文本、规则事件和结构化标签基准提供稳定的样本外增量？

### 3.2 学习顺序

完整的分级论文库、阅读阶段、论文卡和知识退出门见 [R1 论文阅读与知识清单](14_R1论文阅读与知识清单.md)。

1. 金融文本任务：情绪、实体、事件、关系、语义表示；
2. BERT/Embedding、tokenization、pooling 和领域适配；
3. FinBERT 的任务设计与英语金融语料边界；
4. BloombergGPT/FinGPT 的金融语料、评测、开放性与许可边界；
5. RAG 的检索、快照、引用和知识时点；
6. 文本表示的 PIT、去重、人工 gold set 和 OOS 评价。

### 3.3 实验阶梯

| 实验 | 表示 | 评价器 | 目的 |
|---|---|---|---|
| R1-E0 | 无文本 | 固定 evaluator | 收益预测基准 |
| R1-E1 | 规则/词典事件 | 同一 evaluator | 透明文本基准 |
| R1-E2 | 结构化 LLM 标签 | 同一 evaluator | 检验标签增量 |
| R1-E3 | 通用/金融 Embedding | 同一 evaluator | 检验语义表示增量 |
| R1-E4 | PIT RAG 表示 | 同一 evaluator | 检验历史知识增量 |
| R1-E5 | Transformer/微调 | 冻结前述对照 | 只有 E3/E4 通过后立项 |

固定 evaluator 的超参数空间必须在比较文本表示前冻结。模型、prompt、降维、聚合和检索器均计入试验次数。

### 3.4 主要产物

- `TextDatasetManifest` 与许可/PIT/去重报告；
- 人工 gold set 和标注指南；
- `TextRepresentationArtifact`：事件、表示、模型/知识库版本、可得时间、质量状态；
- 无文本/规则/标签/Embedding/RAG 消融；
- 论文候选：金融事件表示对 A 股横截面收益预测的独立增量。

### 3.5 退出门

- 文本许可、时点、实体映射和去重通过；
- 相对无文本和规则基准的增量在多个 OOS 窗口稳定；
- 增量不由少量新闻、未来检索或覆盖缺失解释；
- 若 Embedding/RAG 无增量，允许结论为不支持，并将最简单表示冻结给 R2。

## 4. R2：Machine Learning Alpha Model

### 4.1 中央问题

> 传统金融特征、ESG、市场状态与 R1 冻结文本表示能否通过非线性模型产生相对透明线性/因子基准的稳定 OOS 增量？

### 4.2 输入

```text
传统金融特征
+ ESG 特征
+ R1 冻结 LLM Representation（若 R1 通过）
+ 市场状态/风险特征
        ↓
ML Alpha Model
        ↓
Expected Return / Cross-sectional Rank
```

若 R1 不支持文本增量，R2 继续使用结构化特征，并把“未加入文本”作为正式研究分支，而不是强行保留复杂表示。

### 4.3 学习与模型顺序

1. 横截面资产定价、特征标准化、中性化、IC 与 OOS R²；
2. Ridge/Elastic Net 和正则化；
3. Tree boosting、LightGBM、交互与特征稳定性；
4. 浅层神经网络与低信噪比过拟合；
5. Autoencoder Asset Pricing 的条件因子结构；
6. Deep Learning in Asset Pricing 的深层 SDF/非线性结构。

模型阶梯固定为：

```text
因子/排序基准
→ Ridge/Elastic Net
→ LightGBM（主模型）
→ Random Forest/浅层 MLP（稳健性）
→ AutoEncoder/深层资产定价（条件成熟后）
```

### 4.4 主要实验

- 结构化特征 vs 结构化 + R1 表示；
- 线性 vs LightGBM，固定同一数据、切分和组合器；
- 传统/ESG/文本/市场特征族消融；
- 微盘、流动性、行业、市场状态、成本和执行延迟稳健性；
- 目标置换、特征错位、随机噪声和最终留出保护；
- 全部模型搜索进入 trial family，使用 DSR/PBO 或预注册多重试验控制。

### 4.5 主要产物

- `AlphaPredictionArtifact`：时点、股票、预测/排名、不确定性、模型/特征版本；
- 模型比较、特征族消融、校准和稳定性报告；
- 论文候选：LLM 表示与结构化特征在 A 股机器学习资产定价中的增量与边界。

### 4.6 退出门

- 至少 36 个非重叠真实 OOS 月；
- 相对透明基准的增量跨窗口、成本和流动性条件稳定；
- 复杂度、试验次数或微盘暴露不能解释主要结果；
- 若 LightGBM/深层模型无增量，冻结最简单合格模型进入 R3。

## 5. R3：Portfolio Optimization

### 5.1 中央问题

> R2 冻结预测能否在预测误差、协方差不稳定、交易成本和 A 股约束下，通过组合方法转化为优于 Top-N/1/N/简单风险预算的 OOS 风险调整结果？

### 5.2 学习与方法顺序

1. 均值—方差、估计误差、协方差收缩和 1/N 基准；
2. 风险预算、换手惩罚和现实约束；
3. Black–Litterman 的均衡先验、view、`Omega` 和置信度校准；
4. Deep Portfolio 的端到端权重学习；
5. FinRL/RL 的状态、动作、奖励、离线评价和环境偏差。

实现顺序固定为：

```text
Top-N / 1/N
→ 波动缩放 / 风险预算
→ 稳健均值—风险
→ Black–Litterman + R2 Alpha
→ Deep Portfolio（有增量才进入）
→ RL（仅远期 paper/simulation）
```

### 5.3 主要实验

- 固定同一 R2 预测，只改变组合器；
- 固定同一组合器，比较传统/ML/LLM 增量；
- 成本、滑点、延迟、容量、停复牌和涨跌停压力；
- 预测与协方差扰动下的权重稳定性；
- gross/net、风险贡献、行业/因子暴露和回撤归因；
- RL 不接券商，不作为 PFROS 自动执行模块。

### 5.4 主要产物

- `PortfolioResearchArtifact`：研究权重、输入预测、风险模型、约束、成本和归因；
- Top-N/风险预算/BL/深度方法的公平比较；
- 论文候选：LLM/ML Alpha 在估计误差和 A 股约束下的组合转化效率。

### 5.5 退出门

- 复杂组合相对简单基准的改进在成本后稳定；
- 权重不对输入微扰极端敏感；
- 执行现实性和归因对账通过；
- 若 BL/深度/RL 无增量，保留 Top-N 或简单风险方案。

## 6. 三大方向的接口

```text
R1 TextRepresentationArtifact
        ↓
R2 AlphaPredictionArtifact
        ↓
R3 PortfolioResearchArtifact
        ↓
Research Package
        ↓
PFROS Research Registry
        ↓
DecisionCandidate → 人工批准/拒绝
```

每个接口均需 schema、版本、内容哈希、数据分类、成熟度、适用范围和失败状态。下游不能根据文件名或模型名称推断上游已经通过。

## 7. AI 辅助实现分工

### AI 可以直接承担的工程任务

- 数据/特征 schema、离线注册层、manifest 和哈希校验；
- 文本清洗、去重候选、实体映射候选和人工复核队列；
- PIT/CV splitter、模型 adapter、baseline、回测和归因代码；
- 单元测试、泄漏破坏测试、CLI、报告模板和文档；
- 运行已批准的实验并整理成功/失败证据；
- Research Package exporter/validator 和 PFROS sample 合同。

### AI 不能替代的人工职责

- 数据来源许可、文本使用权和个人隐私授权；
- 研究问题、主要指标、试验预算、停止规则和最终留出冻结；
- 人工 gold set 的最终裁决；
- 对异常、映射、经济机制和替代解释的学术判断；
- 研究结论、论文署名/投稿和 PFROS DecisionCandidate 批准；
- 任何实际资金操作。

### 非主线模块的处理

| 模块 | 默认方式 | 启动条件 |
|---|---|---|
| 数据/特征/PIT/实验/回测/风险 | AI 辅助实现 + 人工验收 | 服务 R1–R3 的最小需求 |
| 异常检测 | AI 可实现旁路原型 | 规则基准稳定，禁止自动删数据 |
| 知识图谱/多模态/基础模型 | 暂不实现 | R1/R2 出现明确、预注册的增量问题 |
| 因果 ML | 独立备选论文，不混入 R1–R3 | 有可识别 treatment 和制度设计 |
| Agentic Research | 最后实现只读/沙箱助手 | R1–R3 工具和合同稳定 |
| 合成数据 | AI 可实现测试/压力工具 | 不替代真实 OOS |
| 隐私与 Human-in-the-loop | PFROS 强制治理 | 从接口设计起启用 |

## 8. WIP 与年度原则

- 同一时间只研究一个主方向；
- 每个方向最多一个主实验和一个学习任务；
- R1 未冻结表示前，不展开 R2 深层模型；
- R2 未冻结预测前，不调 R3 复杂组合；
- AI 工程任务必须绑定当前研究方向，不单独扩建平台；
- 论文阅读产物必须进入论文卡：问题、数据、时点、方法、对照、结果、局限和对本项目的可迁移部分。

## 9. 总完成定义

- R1 形成可复现的文本表示比较，无论增量是否成立；
- R2 形成透明到复杂的 ML Alpha 证据链，无论复杂模型是否晋级；
- R3 形成预测到组合的损耗、成本和风险归因；
- 三个方向通过版本化 artifact 串联，但失败不会被下游掩盖；
- 其他工程能力按需由 AI 辅助实现并通过人工验收；
- 最终只向 PFROS 输出研究证据和决策候选，不自动执行投资。
