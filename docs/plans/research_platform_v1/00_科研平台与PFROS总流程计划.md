# A-LLM 科研平台与 PFROS 总流程计划

## 1. 最终定位

本项目不以“自动炒股系统”为目标，而是建设一个个人级、证据驱动的金融科研与财务决策基础设施：

- **A-LLM Research Lab**：数据治理、因子研究、模型实验、回测、归因和研究证据；
- **PFROS**：个人金融事实、现金流、负债、持仓、绩效、风险、研究登记、人工决策和复盘；
- **Research Package**：两者之间唯一受控的研究交接形式。

```text
外部市场/财务/事件数据
        ↓
A-LLM 数据验收与 PIT 门禁
        ↓
传统基准 → R1 LLM 表示 → R2 ML Alpha → R3 组合与风险研究
        ↓
Research Package + 成熟度判定
        ↓
PFROS Research Registry
        ↓
脱敏持仓比较 → Decision Candidate
        ↓
人工批准、执行与复盘
        ↓
券商/银行事实重新进入 PFROS 账本
```

## 2. 双目标与中央问题

### 2.1 工程目标

任一研究结果都能追溯至数据、特征、研究协议、代码、配置、环境、实验记录、统计检验和输出哈希。

### 2.2 科研问题

第一科研问题（R1）：

> 在严格文本许可、事件时点、去重、PIT 和固定收益评价器下，金融文本表示是否相对无文本、规则事件和结构化标签基准提供稳定的样本外增量？

第二科研问题（R2）：

> 传统金融、ESG、市场状态与 R1 冻结文本表示能否通过机器学习产生相对透明线性/因子基准的稳定样本外增量？

第三科研问题（R3）：

> R2 冻结预测能否在估计误差、交易成本和 A 股执行约束下，通过组合优化转化为优于 Top-N、1/N 和简单风险预算的结果？

平台建设本身是研究支撑条件，不是上述问题的肯定答案。

## 4. 总体阶段

| 阶段 | 目标 | 核心退出门 |
|---|---|---|
| P0 | 冻结可信科研基线 | 哈希、测试、门禁、签署、证据一致 |
| P1 | 建立真实传统研究基准 | ≥36 个非重叠 OOS 月，阶段 2–8 真实证据完整 |
| P2 | 建立轻量科研平台注册层 | Dataset/Feature/Experiment/Artifact Registry 与包合同通过 |
| P4 / R1 | LLM 事件因子 | 文本数据验收，固定 evaluator 下的表示增量成立或被拒绝 |
| P3 / R2 | 结构化 + 文本 ML Alpha | LightGBM 等模型相对透明基准的增量经预注册检验 |
| P5 / R3 | 组合与风险研究 | 冻结预测能转化为成本后、约束后的组合改进 |
| PFROS M0–M4 | 建立可信个人金融事实与分析底座 | 可导入、修正、重放、对账、恢复和复算 |
| PFROS M5–M7 | 接入研究并形成决策闭环 | 成熟度不误判、人工批准不可绕过、执行事实可回流 |

阶段按能力门推进，不因日历年份自动晋级。P3/P4 文件编号为兼容性保留；科研执行顺序以 R1→R2→R3 为准。

## 4.1 优化后的六层科研架构

| 层级 | 核心能力 | 对应计划 | 晋级条件 |
|---|---|---|---|
| L0 证据治理 | 数据许可、PIT、冻结、实验登记、过拟合审计 | P0/P1、模块 03/07/14 | 真实基准可重放 |
| L1 科研数据平台 | 离线特征注册、质量旁路、数据/特征版本 | P2、模块 01/02 | 特征全链路可追溯 |
| L2 金融文本表示 | 标签、Embedding、PIT RAG、固定 evaluator | P4/R1、模块 05 | 表示的严格 OOS 增量成立或被拒绝 |
| L3 Alpha 研究 | 透明基准、Elastic Net、LightGBM、可选深层模型 | P3/R2、模块 04 | 结构化 + 冻结文本表示的增量成立或被拒绝 |
| L4 组合与风险 | 简单组合、BL、动态风险、压力测试 | P5、模块 06/08 | 成本和约束后相对基准有增量 |
| L5 个人决策闭环 | Research Package、PFROS、人工批准、复盘 | PFROS M0–M7、模块 16 | 事实、建议、批准和执行不可混淆 |

基础模型、多模态、Agent、合成数据和 RL 是 L6 探索池，只能在其直接前置能力成熟后立项，不能用来绕过 L0–L5。

## 4.2 三条研究线，而非一个无限扩张系统

1. **三篇连续科研线**：LLM Event Factor → ML Alpha → Portfolio Optimization；
2. **统计机制备选线**：AI/ESG/政策等明确处理的因果设计，不与三大预测研究混写；
3. **AI 辅助工程与治理线**：复现、过拟合、Research Package 和 PFROS 人工决策闭环。

另类数据、知识图谱、基础模型与 Agent 只有能回答上述某一条线的明确问题时才进入实验，不单独以技术堆叠作为成果。

## 5. 研究成熟度

统一使用以下等级：

1. `rejected`：schema、哈希、许可、PIT、证据或方法失败；
2. `engineering_valid`：代码、配置、测试和工程运行成立；
3. `data_accepted`：真实数据许可、PIT、质量、覆盖和冻结已验收；
4. `market_evidence_eligible`：真实非重叠 OOS、成本、消融、过拟合和留出期门禁通过。

最高等级也只能进入 PFROS 的 `DecisionCandidate`，不能自动批准或执行。

## 6. 统一研究原则

- 信号日、执行日、持有期和目标结束日必须分离；
- 最终留出期从 2024-01-01 开始，只用于一次性确认；
- 禁止随机时间切分、未来股票池、未滞后财务数据和同收盘信号同收盘成交；
- 先比较简单模型，再增加复杂模型；
- 结果必须同时报告预测、经济、成本、换手、覆盖、容量、回撤和不确定性；
- 不因结果不显著而放宽预注册门槛；
- sample、短历史和工程 smoke 不得升级为真实市场结论。
- 异常模型只产生审查标记，不自动清洗原始数据；
- RAG、知识图谱和 Agent 的知识库必须是事件时点可见快照；
- 合成数据只用于测试与压力情景，不补足真实 OOS；
- 基础模型先评估/适配，不从零训练；
- 强化学习只保留远期 paper/simulation 候选，不接券商。

## 7. PFROS 反向反馈边界

PFROS 可向 A-LLM 提供脱敏、时点一致的持仓权重、约束和基准视图，用于比较研究候选与当前组合。不得提供账户名、账号、流水备注、身份信息、凭据或未经批准的真实财务明细。

个人实际执行结果属于观察性结果，同时受人工选择和外部事件影响，不能未经因果与数据治理审查自动成为模型训练标签。

## 8. 总完成定义

整个路线完成至少要求：

- 两个仓库可以独立安装、测试和发布；
- A-LLM 有至少一个冻结的真实传统基准和清晰的“不晋级也可接受”结论；
- ML/LLM 实验均有透明对照、消融、成本和留出期证据；
- Research Package 任一文件被修改时校验失败；
- PFROS 能重建个人金融事实并与来源对账；
- 研究候选、人工决策、真实执行和事后复盘可关联；
- 无模型、Dashboard 或 AI 能绕过人工批准修改金融事实或触发交易。
