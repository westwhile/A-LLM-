# PFROS M0–M4：可信个人财务底座并行实施计划

## 1. 文件定位

本文件是 A-LLM 项目中的跨项目协调计划，不是 PFROS 的实现状态。PFROS 当前文档位于独立目录，尚未初始化代码工程；任何 PFROS 文件写入、数据库 migration 或真实财务数据导入都需要在 PFROS 项目中另行批准和执行。

## 2. 总目标

先建立可追溯、可重放、可对账、可恢复的个人金融事实系统，再计算持仓、绩效和风险。PFROS 不应先变成投资信号系统。

## 3. 第一版范围

- 单用户、本地运行；
- 人民币为第一本位币；
- 1–2 个账户；
- 现金、A 股和 ETF；
- 入金、出金、买入、卖出、分红、手续费六类事件；
- 手工模板和一种脱敏 CSV Adapter；
- CLI 或静态 Markdown/HTML 报告；
- 全部先用虚构或脱敏夹具开发和测试。

不包含自动交易、券商写接口、云同步、实时行情、多用户、衍生品和复杂税务。

## 4. M0：架构与范围冻结

### 工作块

- 审查三系统定位：金融事实、研究/计算、决策/学习；
- 审查 ADR 与数据分级；
- 确认 MVP-A 账户、币种、资产、事件和报告范围；
- 确认状态词、WIP、任务卡和人工批准规则；
- 保持 PFROS 与 A-LLM 为两个仓库。

### 验收

- [ ] ARCH-001～004 由用户确认；
- [ ] scope in/out 明确；
- [ ] P0–P3 数据等级和处理规则明确；
- [ ] 数据库、事件定义和真实导入被标记为高风险变更。

## 5. M1：安全工程底座

### 工作块

1. 初始化 Python/Git 工程；
2. 建立隐私、`.gitignore` 和秘密扫描；
3. 分离可提交配置与本地覆盖；
4. 固定 run/evidence 合同；
5. 建立 SQLite migration、回滚和临时库测试；
6. 建立样例数据库备份、恢复和完整性检查；
7. 建立统一质量命令。

### 验收

- 测试和日志不含真实账户、余额、流水或凭据；
- migration 可重复、失败可回滚；
- 样例库可备份并实际恢复；
- 运行证据包含代码、配置、输入、schema、状态和输出哈希。

## 6. M2：可信账本 MVP-A

### 领域不变量

- 事件与分录原子提交；
- 每笔分录在账簿和币种内借贷平衡；
- 金额和数量采用明确精度，不使用二进制浮点存储金额；
- 同一来源重复导入不产生重复事件；
- 未确认批次不能入账；
- 原事件不覆盖，错误通过冲正/更正事件处理；
- 从空库重放得到相同现金和事件状态。

### 工作块

- 六类事件手算基准；
- 科目表、币种、精度、舍入和符号；
- Source/ImportBatch、预览、坏行隔离与确认；
- Financial Book `post` 与 `correct`；
- 账户与现金 as-of 查询；
- 一种脱敏 CSV Adapter；
- 来源→预览→确认→入账→修正→重放→备份恢复垂直切片。

### 验收

每个事件可追溯至 `source_id + import_batch_id + source_row + file_hash`；指定日期与样例账单可对账；修正前后均可审计；恢复后结果一致。

## 7. M3：持仓、估值与对账

### 工作块

- Instrument 主数据及代码/市场/有效期；
- Portfolio Projection 事件重放；
- 成本法 v1 的手算与批准；
- PriceSet 与行情 Adapter；
- 市值、已实现/未实现 PnL；
- 账户、现金、持仓和估值对账；
- 差异类型、金额、原因、状态和阻断规则。

### 验收

- 从空库可重建现金、数量和批次；
- 成本和公司行动口径经人工批准；
- 指定日期资产状态可追溯、可重放、可对账和可恢复；
- 未解释对账差异阻断正式报告。

## 8. M4：绩效、现金流与基础风险

### 工作块

- 冻结收益与现金流口径，入金不计收益；
- 净值、期间收益、TWR 和 XIRR；
- 基准日期严格对齐；
- 波动、回撤、集中度、现金比例和暴露；
- 历史情景与压力测试；
- 资产、行业、现金流和成本归因；
- 个人财务扩展：资产负债表、应急储备、目标和风险预算。

VaR/ES 仅作为后续学习实验，不是可信账本门槛。

### 验收

- 指标可用独立手算或第二实现复核；
- 口径、频率、窗口、缺失和现金处理可见；
- 绩效与基础风险可从事实和估值版本重算；
- 不把投资绩效替代现金流、负债和目标管理。

## 9. 与 A-LLM 的并行关系

- PFROS M0–M2 可与 A-LLM P0–P1 并行；
- PFROS M3–M4 可与 A-LLM P2–P3 并行；
- 在 M3 对账和 A-LLM P0 数据冻结都未完成前，不做真实持仓研究比较；
- PFROS 不复制 A-LLM 原始/标准数据，不读取 A-LLM 内部 CSV 约定。

## 10. 完成定义

M0–M4 完成后，PFROS 应能回答：钱和资产从哪里来、当前有多少、为何得到该结果、能否重建、是否与来源对账、绩效和风险口径是什么。此时仍不自动产生投资决策。
