# 模块 14：实验管理与可复现科研计划

> 优先级：A；从 P0 开始贯穿全部模块。先做轻量内容寻址注册层，再评估 MLflow/W&B。

## 1. 中央问题

能否从任何图表、指标或 Research Package 反向定位到唯一的数据、特征、协议、代码、环境、模型、试验族和人工批准，并在冻结输入上重放？

## 2. 四类注册对象

- `DatasetRegistry`：来源、许可、时间范围、schema、PIT、哈希、验收状态；
- `FeatureRegistry`：定义、输入、代码、时点、版本、覆盖和输出哈希；
- `ExperimentRegistry`：假设、切分、模型、参数、seed、试验族、状态和结果；
- `ArtifactRegistry`：指标、预测、交易、图表、报告、日志和 manifest。

## 3. ID 与状态

建议内容：

```text
dataset_id / feature_set_id / protocol_id / experiment_id / run_id
parent_experiment_id / trial_family_id / research_package_id
```

状态至少区分 `planned → running → failed/review → accepted/rejected`；运行成功不能自动成为研究接受。

## 4. 最小实现

1. JSON/YAML registry + schema 校验；
2. SHA-256 manifest 与相对路径；
3. Git dirty 状态、代码 diff/hash、Python/依赖/OS 元数据；
4. 所有 trial（含失败）登记；
5. artifact 不可静默覆盖；
6. 一条命令验证 Research Package 完整性；
7. 一条只读命令生成实验谱系。

## 5. MLflow / W&B 评估规则

- 先用本地 registry 完成核心合同；
- 比较离线可用、数据位置、隐私、锁定、导出、长期可读性和依赖成本；
- 工具只做 UI/追踪增强，不能成为唯一证据库；
- 外部云服务不得接收个人财务明细或未授权数据。

## 6. QA 与破坏测试

- 修改 artifact 一字节，manifest 校验失败；
- 缺一个失败 trial，试验族审计失败；
- 脏工作树仍能记录准确 diff/hash，不能伪称 clean；
- 不同环境重放披露数值容差；
- 引用、图表源数据和报告结论互相链接；
- sample/synthetic/real 使用不可混淆的 data classification。

## 7. 退出门

- 任意结果可追溯到唯一谱系；
- 失败、跳过和人工决策有记录；
- artifact 篡改和 schema 漂移 fail-closed；
- 重放协议在第二环境或干净副本通过；
- registry 不依赖外部服务即可读取与验证。
