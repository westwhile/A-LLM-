# 模块 13：Agentic 量化研究计划

> 优先级：C；Agent 是受控研究助手，不是自主研究结论生成器，更不是交易执行者。

## 1. 中央问题

在固定工具、权限、预算和验收合同下，Research Agent 能否减少可复现研究任务的人工时间，同时不增加数据泄漏、证据遗漏、不可追溯试验或越权操作？

## 2. 允许与禁止

### 允许

- 在冻结数据上提出假设、生成任务卡、运行已批准实验；
- 检查 schema、测试、manifest、引用和报告一致性；
- 汇总成功与失败试验并生成待审草稿。

### 禁止

- 自行联网拉取未授权数据、读取密钥或个人财务明细；
- 修改 final holdout 规则、隐匿失败试验或自行把结果晋级；
- 写入 PFROS 账本、批准 DecisionCandidate、下单或连接券商；
- 自动 commit/push/deploy。

## 3. 最小架构

```text
Research Question + Approved Task Card
        ↓
Planner（只生成步骤和预算）
        ↓
Tool Executor（白名单、沙箱、只对批准范围写入）
        ↓
Evidence Verifier（测试、哈希、PIT、引用、试验登记）
        ↓
Human Review
```

多 Agent 只有在单 Agent 基准无法满足职责隔离时才采用。角色数量不是科研创新。

## 4. 研究任务集

- 数据 manifest 检查；
- 已知泄漏测试定位；
- 小型模型对比实验；
- 文献元数据核验；
- 运行报告与 artifact 一致性；
- 失败试验归因。

每项建立 gold answer、允许工具、最大时长/调用、禁止动作和人工评分。

## 5. 评价指标

- task success、事实/引用准确率、可重放率；
- 未登记试验数、越权尝试、错误晋级、PIT 漏检；
- 人工复核分钟、计算/调用成本；
- 与模板脚本、单 Agent、多人工作流对比。

负对照：带诱导的“跳过门禁”任务、缺文件、冲突证据、被篡改 artifact、最终留出访问请求。

## 6. 实现阶段

1. 只读 QA Agent；
2. 沙箱内运行批准脚本；
3. 生成实验草稿但必须人工启动；
4. 角色分离与审计；
5. 只有长期稳定后才允许创建待审任务，不允许自主研究循环。

## 7. 退出门

- 权限默认为拒绝，所有工具调用有审计记录；
- Agent 不能绕过数据、留出、晋级和人工批准门；
- 相对非 Agent 基准节省时间且错误率不增加；
- 失败可恢复，副作用范围可证明；
- 任一越权或证据隐匿为阻断缺陷。
