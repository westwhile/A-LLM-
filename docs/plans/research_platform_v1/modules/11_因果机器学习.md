# 模块 11：因果机器学习计划

> 优先级：B；适合统计科研支线。预测收益不是因果问题，必须先定义处理、结果、时点和识别假设。

## 1. 候选中央问题

可选但不可混合：

- 企业 AI 采用是否影响未来经营/ESG 指标？
- 特定政策或事件冲击是否改变相关企业的经营或市场反应？
- LLM 事件标签识别出的处理是否存在异质性影响？

“AI 新闻多的股票以后收益高”本身只能是预测关联，不能直接写成因果效应。

## 2. 因果问题合同

```yaml
estimand: ATE / ATT / CATE / event-time effect
treatment:
outcome:

confounders_available_before_treatment: []

```

必须先画 DAG，区分混杂、媒介、碰撞变量和处理后变量。

## 3. 方法阶梯

### M0 设计优先

- 事件研究、DiD、匹配/加权、固定效应；
- 检查平行趋势、预趋势、处理时点和同期冲击；
- 优先寻找可辩护的制度/政策设计，而不是先选算法。

### M1 Double/Debiased ML

- 使用正交得分和 cross-fitting 估计高维 nuisance；
- 时间/公司聚类和面板依赖需专门处理，不能直接套 i.i.d. 示例；
- DML 减少正则偏差，不自动解决未观测混杂或错误识别。

### M2 异质性

- causal forest/CATE 需预注册目标人群和验证方式；
- 不能事后挑选“最有效”子组；
- 机制解释需中间结果或独立证据。

## 4. 实验与稳健性

- overlap、协变量平衡、预趋势和 placebo date；
- 负对照结果/处理、未受影响行业和伪事件；
- 不同时间窗、聚类标准误、样本限制和同期政策；
- 未观测混杂敏感性；
- 将预测任务和因果任务使用不同实验登记与结论语言。

## 5. 实现块

1. 因果问题/DAG/estimand 注册；
2. 时点化处理与面板构建；
3. 透明设计基准；
4. DML nuisance pipeline 与 cross-fitting；
5. placebo、balance、sensitivity 和异质性；
6. 因果证据包，不直接成为交易信号。

## 6. 退出门

- 处理、结果和 estimand 明确；
- 识别假设有制度和数据证据，不只因模型复杂；
- overlap/预趋势/安慰剂和敏感性达到预注册标准；
- 结论区分统计显著、经济意义和外部有效性；
- 无法识别时降级为关联/预测研究，不强行使用因果措辞。
