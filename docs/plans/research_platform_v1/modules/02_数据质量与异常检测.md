# 模块 02：数据质量与异常检测计划

> 优先级：B；角色是规则质量门的增强旁路，不是把统计清洗替换成黑箱删除器。

## 1. 中央问题

在不破坏原始数据、PIT 和可解释性的前提下，Isolation Forest 或 AutoEncoder 是否能发现规则检查遗漏的多变量异常，并提高人工审查效率？

## 2. 基本原则

- 原始层只读；标准层的修正必须有来源、理由和版本；
- 模型输出 `anomaly_score`、原因线索和审查状态，不自动删除、Winsorize 或填补；
- 价格跳变、涨跌停、复权切换、财报口径变化可能是真实事件，不能等同脏数据；
- 每个行业、规模、时期的正常分布不同，避免用全市场单一阈值误伤。

## 3. 假设

- H1：多变量模型相对现有规则能提高已知错误样本的召回率；
- H2：在固定人工复核预算下，模型排序能提高确认错误的命中率；
- H0：模型只是在重复标记极值或市场真实冲击，不能提供增量。

## 4. 候选方法

### M1：规则与稳健统计基线

- schema、主键、范围、跨表一致性、复权连续性、时间可得性；
- median/MAD、行业—时间分组的稳健 z-score；
- 已知企业行动和交易制度白名单。

### M2：Isolation Forest

- 输入先做时间/行业分组和缺失标识；
- 只在训练窗口拟合，对下一窗口评分；
- 与单变量规则比较增量，不把 `fit_predict=-1` 当真值。

### M3：AutoEncoder / DAGMM

- 只有样本量、特征稳定性和 M2 证据充分后才进入；
- 重构误差需要按时期校准；
- 深度模型必须与 PCA/稳健协方差基准比较。

## 5. 标注与实验设计

- 建立 `quality_incident` 表：错误类型、来源证据、发现方式、修正版本、复核人；
- 使用历史已确认错误 + 受控注入错误评估，不仅看无标签异常分数；
- 注入：数量级错误、单位错、日期错位、重复、字段交换、复权断点、未来财报；
- 指标：precision@review_budget、recall by error type、误报率、跨期稳定性、人工分钟/确认错误；
- 负对照：真实涨跌停、停牌复牌、行业冲击和财报大幅改善。

## 6. 交付物

- `AnomalyReport` 合同与 score 版本；
- 规则/IForest/AutoEncoder 对比报告；
- 人工复核队列和审查结果；
- 误报案例册；
- 不可自动执行的治理说明。

## 7. 退出门

- 所有标记能追溯输入与模型版本；
- 模型在冻结验证集上相对规则有明确增量，且误报在预算内；
- 不改变原始数据；
- PIT 问题由专门 PIT 门处理，而不是被异常模型掩盖；
- 未达门槛时保留规则系统，记录负结果。
