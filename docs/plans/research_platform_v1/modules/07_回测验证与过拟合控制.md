# 模块 07：回测验证与过拟合控制计划

> 优先级：A；贯穿 P1–P5。它是研究审计层，不是多产出几个绩效指标。

## 1. 中央问题

观察到的样本外结果在多重试验、非正态收益、有限样本、执行约束和策略选择偏差下仍有多少可信度？

## 2. 偏差清单

- look-ahead、survivorship、股票池和财报发布时间错误；
- 重叠标签、全样本标准化/降维、final holdout 污染；
- 对同一数据反复调因子、参数、prompt 和组合约束；
- 低估成本、滑点、停牌、涨跌停和成交容量；
- 只汇报最佳策略，遗漏失败试验和人工筛选。

## 3. 实现块

### M1 事件驱动执行现实性

- 信号、订单、成交、持仓和收益时点分离；
- T+1、不可交易、部分成交、现金、公司行动和退市；
- 成本模型按成交额/流动性分层，并给压力情景。

### M2 金融验证

- 复用模块 03 的区间审计、purged walk-forward 和 final holdout；
- 每折输出训练/验证/测试样本与模型哈希；
- 不用普通随机 CV。

### M3 多重试验登记

- `trial_id` 覆盖模型、特征、prompt、参数、过滤和组合规则；
- 记录有效试验族，不只记录最后一次正式运行；
- 预注册主指标和 model-selection budget。

### M4 PBO / DSR

- PBO 只有在可定义可比较的策略试验矩阵时实施；
- DSR 需要样本长度、偏度、峰度和试验选择信息；
- 两者是补充证据，不替代真正的时间向前 OOS 和最终留出。

### M5 可微回测（长期）

- 只作为研究支线；若损失函数/成交近似与实际模拟不一致，不能用梯度结果替代事件驱动回测；
- 必须与两阶段“预测→组合→回测”基准比较。

## 4. 报告矩阵

- 样本区间、频率、股票池、持有期和复权；
- 成本/滑点/成交/容量；
- 年化收益、波动、Sharpe/Sortino/Calmar、最大回撤；
- IC、Rank IC、分组单调性、换手和覆盖；
- bootstrap/区间估计、DSR/PBO（若适用）；
- 状态、行业、规模、流动性和年份分解；
- 失败模型和留出期访问记录。

上述报告矩阵就是本模块的实验设计：同一冻结预测、股票池和执行协议下，只改变验证/成本/试验控制条件，避免把模型变化与回测审计变化混在一起。

## 5. 负对照与破坏测试

- 打乱预测、反转信号、滞后一周期、随机股票池；
- 将成本提高 2–3 倍；
- 去除最优年份/最小市值组；
- 把关键 PIT 字段故意设错，gate 必须阻断；
- 运行 artifact 被修改后 manifest 校验必须失败。

## 6. 退出门

- 真实 OOS 与 sample/smoke 完全分开；
- 每个结果可追溯全部试验和选择路径；
- 最终留出只有一次正式确认；
- 结论同时披露统计和经济不确定性；
- 不能通过删失败窗口、放宽成本或扩大参数搜索“修复”结论。
