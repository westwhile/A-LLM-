# P0：A-LLM 科研基线冻结实施计划

## 1. 目标

把“当前工程和数据门禁已运行”转化为一个可重复、可审查、可引用的科研基线。P0 不评价策略有效性，也不启动新模型。

## 2. 当前输入

- 当前主线：`A-LLM-`；
- 最新真实标准目录：`data/standard/real-pit-20260725-r1/`；
- 最新门禁目录：`reports/gate/real-pit-20260725-r1/`；
- 当前门禁摘要为 `passed`，但工作树、签署表与 manifest 哈希尚未形成统一冻结状态；
- 旧状态文档存在快照漂移。

## 3. 范围

### 范围内

- 只读核对现有修改、数据 manifest、来源登记、研究协议和门禁证据；
- 重新计算并核对哈希；
- 重新执行完整测试与质量门禁；
- 生成冻结候选清单、验收收据和状态更新建议；
- 用户完成必要的哈希确认和终审签署。

### 范围外

- 新增因子、模型或回测参数；
- 查看最终留出期表现后修改研究协议；
- 自动 commit、tag、push、删除旧批次或覆盖受限数据；
- 由 AI 代替用户签署。

## 4. 工作包

### P0-W1：工作树分类

1. 保存 `git status --short`、`git diff --stat` 和目标文件清单；
2. 将修改分类为数据来源/口径、代码、测试、报告、运行证据和临时文件；
3. 对每项修改记录来源、目的、授权和对应测试；
4. 不恢复或覆盖用户未提交修改。

产物：`baseline_change_inventory.md`、diff 或 source-tree 哈希。

### P0-W2：数据与协议一致性

1. 核对 `data_manifest.json` 的来源登记哈希、表级哈希、行数和日期范围；
2. 重新计算 `config/data_source_registry.yaml` 与 `config/research_protocol.real.yaml` 的 SHA-256；
3. 与签署清单 B 对比；任何不一致都必须重新审查，不得沿用旧勾选；
4. 核对 C 部分所有豁免、数据警告和适用范围。

产物：`baseline_hash_reconciliation.md`。

### P0-W3：工程验证

在 `A-LLM-/` 下使用项目虚拟环境：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

同时运行项目已有质量入口、配置合同检查和必要 smoke。记录 Python、依赖版本、测试数、失败/跳过和运行时间。

产物：`baseline_test_receipt.md`、机器可读测试摘要。

### P0-W4：真实数据门禁复核

对新 `run_id`/新门禁目录执行质量与五类专项审计，禁止覆盖旧目录。必须核对：

- `data_gate_summary.status=passed`；
- blocking 为空；
- PIT、财务修订、幸存者、覆盖率、基准对齐均非空且通过；
- 27 类或后续 warning 均有影响说明，不因 warning 自动删除数据；
- 豁免只影响已批准字段与分母，逐日计数可审计。

### P0-W5：人工签署与冻结

1. 用户确认最新登记表和协议哈希；
2. 用户逐项确认 C 终审条目；
3. 生成冻结收据，绑定代码、diff/source tree、配置、数据 manifest、门禁与签署文件；
4. 是否 commit/tag/push 由用户另行决定。

## 5. 验收标准

- [ ] 工作树状态和每项在途修改均有归属；
- [ ] 登记表、协议、manifest 和签署哈希一致；
- [ ] 完整测试与质量入口通过；
- [ ] 新门禁目录为 `passed`，专项审计完整；
- [ ] warning、豁免和剩余限制有记录；
- [ ] 用户完成 B 哈希确认和 C 终审签署；
- [ ] 冻结收据可定位全部证据；
- [ ] 未查看留出期结果后修改协议；
- [ ] 未自动执行 Git 发布动作。

## 6. 失败处理

任一哈希不一致、测试失败、专项审计为空、签署缺失或门禁阻断，都将 P0 状态保持为 `blocked` 或 `review`。不得为了进入 P1 修改门槛或把失败标记为 warning。

## 7. 完成后下一步

只有 P0 为 `accepted`，才允许执行 P1 的真实阶段 2–8 研究。P2 仅可提前设计 schema，不得用未冻结真实结果验证晋级逻辑。
