# 任务依赖、WIP 与里程碑计划

## 1. 关键路径

```text
A-LLM:
P0 基线冻结
  → P1 真实传统基准
  → P2 平台注册层
  → P3 结构化 ML Alpha
  → P4 LLM 增量（需文本数据门禁）
  → P5 组合与风险

PFROS:
M0 架构
  → M1 安全底座
  → M2 可信账本
  → M3 持仓估值对账
  → M4 绩效风险
  → M5 Research Package
  → M6 决策复盘
  → M7 运行与 AI 加固

交汇:
A-LLM P2 + PFROS M3 → sample 合同/脱敏持仓视图
A-LLM P3/P4/P5 通过 + PFROS M4 → 真实 DecisionCandidate
```

## 2. 并行泳道

### 泳道 A：A-LLM 科研

当前只允许一个主实施任务。优先顺序：P0 → P1 → P2 → P3。P4/P5 不提前占用主线资源。

### 泳道 B：PFROS 财务底座

可与 A 并行，但实际 PFROS 写入必须在独立项目授权。优先 M0 → M1 → M2，不因 A-LLM 模型结果提前做投资接入。

### 泳道 C：学习与论文

每次最多一个理论学习任务，必须与当前实施块绑定。例如 P1 对应状态空间/波动与过拟合，P3 对应横截面 ML 与时间序列验证。

## 2.2 建议学习顺序

1. 数据/PIT/回测偏差：模块 01、03、07、14；
2. 统计学习与横截面资产定价：模块 04；
3. 文本数据治理与金融表示：模块 05；
4. 风险、组合与压力：模块 06、08；
5. 因果识别：模块 11，可与第 3–4 步形成独立论文线；
6. 图、多模态、基础模型、Agent、合成数据：只按具体研究问题选一个，不整组学习。

## 3. WIP 限制

- 最多 1 项项目实现任务；
- 最多 1 项理论学习任务；
- 最多 1 项等待人工审查的高风险变更；
- 不同时启动 ML、LLM、组合优化和 PFROS 接入；
- 长期探索池最多同时保留 1 个可行性 spike，且不得占用主实现 WIP；
- 未通过退出门时，下一阶段只允许设计，不允许宣称实现。

## 4. 里程碑

| 里程碑 | 对应阶段 | 完成条件 | 粗略活动时间 |
|---|---|---|---|
| R0 冻结科研基线 | P0 | 哈希、测试、门禁、签署一致 | 2–4 周 |
| R1 真实传统基准 | P1 | ≥36 OOS 月、阶段 2–8、留出收据 | 1–2 月 |
| R2 科研平台注册层 | P2 | 四类 registry 与包合同 | 1–2 月 |
| R3 第一条 ML 研究 | P3 | 透明基准、ML 增量、消融与留出 | 2–4 月 |
| R4 LLM 事件研究 | P4 | 文本门禁、人工复核、独立增量 | 3–6 月，受数据影响 |
| R5 组合与风险 | P5 | 复杂方案相对简单基准的成本后证据 | 2–4 月 |
| F1 可信账本 | PFROS M0–M2 | 来源到恢复垂直切片 | 4–7 月 |
| F2 可解释组合 | PFROS M3–M4 | 对账、绩效、风险可复算 | 5–9 月 |
| F3 决策闭环 | PFROS M5–M7 | 包验证、候选、批准、回流、复盘 | 双门禁后 4–8 月 |

模块 09/10/12/13/15 和 RL 不设置日历里程碑；它们只有在研究问题、数据/许可、基准、资源和停止条件齐全时才进入可行性评估。

时间是项目活动量估计，不是承诺日期。考试、数据许可、人工审查和返工不计入。

## 6. 启动检查

任务进入 `in_progress` 前确认：

- 前置 gate 已 `accepted`；
- 当前磁盘文件已读取；
- 目标路径、修改文件和禁止目录明确；
- 数据、网络、依赖、Git 和外部服务授权明确；
- 测试、证据、恢复和停止条件明确；
- 不会覆盖用户未提交修改。

## 7. 完成检查

- 产物与任务卡一致；
- diff 仅包含批准范围；
- 测试/门禁实际运行并记录；
- 失败、跳过和未验证项披露；
- 文档与代码状态同步；
- 需要人工批准的状态仍为 `review`；
- 不自动 commit/push/tag/deploy。

## 8. 变更控制

若任务范围扩大，先新增或修改任务卡并重新审查，不把新模型、数据源、外部 API 或 PFROS 真实数据隐式加入现有任务。
